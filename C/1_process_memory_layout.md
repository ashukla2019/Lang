# Why Memory is Divided into Segments

A running process contains many different kinds of data.

For example,

- Machine instructions
- Global variables
- Static variables
- Local variables
- Dynamically allocated memory
- String literals

If everything were placed in one large memory block:

- Memory management becomes difficult.
- Security becomes weaker.
- Memory protection becomes impossible.
- Efficient allocation becomes harder.

Therefore, the operating system divides memory into multiple logical sections.

---

# Process Virtual Memory Layout

A typical process looks like:

```
High Address
+----------------------------+
| Command-line Arguments     |
| Environment Variables      |
+----------------------------+
|            Stack           |
|            ↓               |
| Function Calls             |
| Local Variables            |
+----------------------------+
|                            |
|      Free Virtual Space    |
|                            |
+----------------------------+
|            Heap            |
|            ↑               |
| malloc() / calloc()        |
| realloc()                  |
+----------------------------+
| BSS Segment                |
| Uninitialized Globals      |
| Uninitialized Statics      |
+----------------------------+
| Data Segment               |
| Initialized Globals        |
| Initialized Statics        |
+----------------------------+
| Read-Only Data (.rodata)   |
| String Literals            |
| const Global Data          |
+----------------------------+
| Text Segment (.text)       |
| Program Instructions       |
+----------------------------+
Low Address
```

> **Interview Insight:** Every systems interview expects you to draw this layout.

# Text Segment (.text)

The Text segment contains the machine instructions generated by the compiler.

Example:

```c
#include <stdio.h>

void printHello(void)
{
    printf("Hello\n");
}

int main(void)
{
    printHello();
    return 0;
}
```

Functions stored here:

- main()
- printHello()

Characteristics:

- Read-only
- Executable
- Shared among processes running the same executable
- Cannot be modified during execution

Attempting to modify code results in undefined behavior and usually a segmentation fault.

---

# Read-Only Data (.rodata)

This section stores read-only constants.

Example:

```c
char *msg = "Hello";
```

The string

```
"Hello"
```

is stored in `.rodata`.

The pointer `msg` itself is stored elsewhere depending on its storage class.

Memory:

```
.rodata

+-----------+
| "Hello"   |
+-----------+
```

Attempting to modify it:

```c
char *msg = "Hello";

msg[0] = 'h';
```

Often results in:

```
Segmentation Fault
```

---

## Interview Question

Why?

Because string literals are stored in read-only memory.

---

# Data Segment (.data)

Stores initialized global and static variables.

Example:

```c
int global = 10;

static int count = 20;
```

Memory:

```
Data Segment

global = 10

count = 20
```

Characteristics:

- Exists for the entire lifetime of the program
- Created before `main()`
- Destroyed after the program exits

---

# BSS Segment (.bss)

Stores global and static variables that are not explicitly initialized.

Example:

```c
int global;

static int count;
```

Although not initialized by the programmer, both are automatically initialized to zero.

Equivalent to:

```c
int global = 0;
static int count = 0;
```

The loader zero-initializes this memory before `main()` begins.

---

## Why Separate Data and BSS?

Consider:

```c
int a = 10;
int b;
```

If both were stored in the executable, the file would contain unnecessary zero bytes.

Instead:

- `.data` stores actual initialized values.
- `.bss` stores only the required size.

This reduces executable size.

---

# Heap

The Heap is used for dynamic memory allocation.

Allocated using:

```c
malloc()

calloc()

realloc()
```

Freed using:

```c
free()
```

Example:

```c
int *arr = malloc(10 * sizeof(int));

free(arr);
```

Heap grows upward.

```
Heap

malloc()

↓

More Memory
```

Characteristics:

- Programmer manages memory.
- Allocation is slower than the stack.
- Can grow while the program is running.
- Memory leaks occur if memory is not freed.

---

# Stack

The Stack stores:

- Local variables
- Function parameters
- Return address
- Saved registers
- Stack frames

Example:

```c
void fun(void)
{
    int x = 5;
}
```

`x` is stored on the stack.

The stack grows downward.

```
Stack

main()

↓

fun()

↓

anotherFunction()
```

Each function call creates a new stack frame.

---

# Stack Frame

Example:

```c
void add(int a, int b)
{
    int sum = a + b;
}
```

Stack frame:

```
+----------------------+
| Return Address       |
+----------------------+
| Saved Registers      |
+----------------------+
| Parameter a          |
+----------------------+
| Parameter b          |
+----------------------+
| Local Variable sum   |
+----------------------+
```

When the function returns, the entire frame is removed automatically.

---

# Function Call Example

```c
#include <stdio.h>

void square(int x)
{
    int result = x * x;
    printf("%d\n", result);
}

int main(void)
{
    int n = 5;

    square(n);

    return 0;
}
```

Execution:

```
main()

↓

Create Stack Frame

↓

Call square()

↓

Create New Stack Frame

↓

Return

↓

Destroy square() Frame

↓

Destroy main() Frame
```

# Why Returning a Local Variable is Wrong

Example:

```c
int *fun(void)
{
    int x = 10;

    return &x;
}
```

Memory:

```
Stack

+--------+
| x = 10 |
+--------+

Return

↓

Stack Frame Destroyed
```

The returned pointer points to memory that no longer belongs to the function.

This is called a **dangling pointer**.

Correct solution:

```c
int *fun(void)
{
    int *ptr = malloc(sizeof(int));

    *ptr = 10;

    return ptr;
}
```

Remember to call:

```c
free(ptr);
```

when finished.

---

# Stack vs Heap

| Stack | Heap |
|--------|------|
| Automatic allocation | Manual allocation |
| Fast | Slower |
| Small | Large |
| Auto deallocation | Must call free() |
| Managed by compiler/runtime | Managed by programmer |
| Function-local storage | Dynamic storage |

---

# Stack Overflow

Example:

```c
void fun(void)
{
    int arr[1000000];

    fun();
}
```

Every recursive call creates another stack frame.

Eventually:

```
Stack

↓

No More Space

↓

Stack Overflow
```

---

# Memory Leak

Example:

```c
void fun(void)
{
    int *p = malloc(100);

    // Forgot free()
}
```

Memory remains allocated after the pointer is lost.

Repeated leaks eventually exhaust available heap memory.

---

# Variable Lifetime

```c
int global = 10;

void fun(void)
{
    static int s = 0;

    int x = 5;
}
```

| Variable | Memory | Lifetime |
|----------|--------|----------|
| global | Data | Entire Program |
| static s | Data | Entire Program |
| x | Stack | Function Call |

---

# Variable Scope vs Lifetime

These are different concepts.

## Scope

Where the variable can be accessed.

## Lifetime

How long the variable exists in memory.

Example:

```c
void fun(void)
{
    static int count = 0;
}
```

Scope:

```
Only inside fun()
```

Lifetime:

```
Entire Program
```

# Common Interview Questions

### Q1. Where are global variables stored?

Initialized globals:

```
Data Segment
```

Uninitialized globals:

```
BSS Segment
```

---

### Q2. Where are local variables stored?

```
Stack
```

---

### Q3. Where does malloc() allocate memory?

```
Heap
```

---

### Q4. Which grows upward?

```
Heap
```

---

### Q5. Which grows downward?

```
Stack
```

---

### Q6. Why is stack allocation faster?

Because allocating on the stack usually only adjusts the stack pointer.

Heap allocation requires allocator bookkeeping, searching for suitable blocks, and synchronization in multithreaded programs.

---

### Q7. What is a Stack Frame?

The memory created for each function call containing:

- Parameters
- Local variables
- Return address
- Saved registers

---

### Q8. Why can't we return the address of a local variable?

Because the stack frame is destroyed after the function returns.

The pointer becomes a dangling pointer.

# Interview Traps

### Trap 1

```c
char *p = "Hello";

p[0] = 'h';
```

Wrong.

Reason:

String literals are stored in read-only memory.

---

### Trap 2

```c
int *fun(void)
{
    int x = 10;

    return &x;
}
```

Wrong.

Reason:

Returning the address of a local variable creates a dangling pointer.

---

### Trap 3

```c
int *p = malloc(sizeof(int));

p = NULL;
```

Memory leak.

The allocated memory can no longer be freed because its address has been lost.
